# Якорь (portable-os-admin)

Дипломный проект Максима: защищённый доступ к рабочим местам организации с
переносных загрузочных устройств. Состоит из четырёх частей:

| Компонент | Где в коде |
|---|---|
| приложение администратора (Tkinter) | `src/portable_os_admin/gui/`, `admin/`, `config/`, `container/` |
| сборка и запись переносного устройства (Debian, РЕД ОС) | `src/portable_os_admin/install/`, `install/backends/` |
| программы на устройстве (доступ, VPN, RDP/VNC/SSH, сетевой экран) | `src/portable_os_admin/install/access/runtime/` |
| сервер доступа и управления | `packaging/revocation-server/` |

Подробная карта — `docs/PROJECT-OVERVIEW.md`.

## Терминология

- Решение называется «Якорь». Прежние названия («Шлейф», «Ткач», «Нить») в новый текст не пишем.
- Технические имена `portable-os-admin`, `portable_os_admin`, `poa-*`, пути и идентификаторы протокола **не переименовываем**: от них зависят установленные системы.
- Роли: администратор, администратор носителя, сотрудник, владелец корня. Голое слово «владелец» не используем (SOLUTION.md, 2.1).

## Правила работы (против лупа)

С 04.10.2026 по 15.11.2026 код почти не менялся: всё время ушло на документы, схемы и переименования. Чтобы это не повторилось:

- **Задача = изменение кода + тест.** Документ правится только в той мере, в какой его затрагивает изменение.
- Без прямой просьбы **не** создаём новых документов, схем draw.io и «карт проекта», ничего не переименовываем, не проводим повторных «проверок по нормативам» и «поиска дыр».
- Найденный пробел в целевом решении записываем вопросом к Максиму, а не расширяем решение сами.
- Работаем по одной задаче за раз: воспроизвели → нашли причину → исправили → проверили.
- Отметку «проверено вживую» ставим, только когда реально прогнали на Linux или на стенде. Если прогона не было, так и пишем: не проверено.

## Команды

Linux, Python ≥ 3.9. На Windows тесты не работают: нет `fcntl`, а часть тестов создаёт мусорные файлы в корне репозитория. Используйте WSL Ubuntu.

```sh
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/python -m pytest -q --basetemp=/tmp/yakor-tests      # короткий basetemp: иначе не хватает длины пути UNIX-сокета
.venv/bin/python -m pytest -q tests/test_gui.py                 # нужен дисплей (или Xvfb)
.venv/bin/python -m pyflakes src packaging/revocation-server    # обязательно: ловит ошибки, которые тесты пропускают
```

Пакеты собираются через `packaging/build-deb.sh` и `build-rpm.sh`, CI — в `.github/workflows/`. Живые проверки (сборка, запись, загрузка в QEMU, сервер) идут на стенде `posvm`, см. `tools/stand/README.md`. Доступен ли стенд сейчас — неизвестно.

## Соглашения кода

- Единственная зависимость во время работы — `cryptography>=2.6`: пакет ставится без интернета, из пакетов дистрибутива. **Новых зависимостей не добавлять.**
- Комментарии на русском: объясняют *почему*, часто с датой и случаем, на котором это всплыло. Стиль сохраняем.
- Скрипты `recovery/*.sh` попадают в пакет по маске (`pyproject.toml`). Новые файлы, которые едут на носитель, должны в эту маску попадать.
- Права администратора приложение получает через polkit (`gui/elevate.py`, `packaging/polkit/`), а не своими силами.
- Коммиты: `Область: суть` по-русски, например `Э9: докачка при обрывах`.

## Блокеры по оборудованию
