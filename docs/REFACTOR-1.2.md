# Рефакторинг 1.2.0: пересборка слоёв

Файл задачи. Обновляется по ходу работы, а не в конце: решения и их причины
записываются здесь в тот момент, когда принимаются.

## Цель

Привести код в состояние, где новая вещь физически попадает во все пути, где
она нужна, а не в один из них. Поводом стали два дефекта 1.1.0, найденные
только живой загрузкой и оба одного рода — «сведения возят не оттуда, где они
родились»:

- ID носителя восстанавливали из имени dm-отображения (`rsplit("-", 1)[-1]`), и
  с приставкой администратора носитель стал спрашивать сервер о половине своего
  идентификатора;
- два пути записи носителя (установка и развёртывание) писали его файлы
  каждый по-своему — долг 33, четыре дефекта за два дня.

## Границы

**Входит:** выделение явных границ между слоями (конфигурация → установщик →
бэкенды → генераторы файлов носителя → интерфейс), разбиение разросшихся
модулей, устранение дублирования, единый стиль, приведение документации в
соответствие с кодом.

**Не входит:** новые возможности, смена протокола отзыва, формат контейнера,
замена tkinter, поддержка новых семейств. Поведение, подтверждённое живыми
прогонами 1.1.0, должно остаться ровно таким же.

**Критерий готовности:** 774 теста проходят под Xvfb (эталон снят на выпущенном
коммите 16.09.2026, код возврата 0); живые прогоны обоих
семейств (Debian + MATE, РЕД ОС + KDE) от сборки дистрибутива до отзыва и
самоуничтожения повторены и дают то же, что в 1.1.0.

## Декомпозиция

Зоны не пересекаются по файлам — это условие для параллельной работы воркеров
в отдельных worktree.

| | Зона | Файлы | Статус |
|---|---|---|---|
| Р1 | Сведения о носителе едут одним объектом (`MediaIdentity`: ID, UUID томов, ключи) вместо россыпи аргументов | `install/disk.py`, `install/installer.py` | **закрыта** 16.09.2026: объект введён, и его принимают все точки входа — `_install`, `_deploy`, `_prepare_medium`, `_write_medium_identity`, `_install_recovery_boot`. Ключи и коды восстановления ложатся в него в месте рождения. Помощники монтирования и описи по-прежнему берут только раскладку: им больше и не нужно, а передавать туда всё удостоверение значило бы расширять доступ без нужды |
| Р2 | Бэкенды: разделить «что за система» и «какие файлы пишем» | `install/backends/*` | **закрыта частично** 16.09.2026: тексты (тема и сценарий plymouth, fstab, crypttab) вынесены в `backends/text/`, константы — в `backends/constants.py`, методы класса стали переходниками. Разрезание самого класса на слои **отложено сознательно**: и Debian, и РЕД ОС переопределяют методы во всех четырёх группах (пакеты, файлы, загрузчик, chroot), такая правка тянет оба потомка сразу, а доказывается только живой загрузкой. Полный набор после зоны — 774 теста, ровно эталон |
| Р3 | Отзыв: разнести генератор скрипта, юниты, шлюз и хвост уничтожения | `install/revocation.py` | **закрыта** 16.09.2026: пакет из семи модулей плюс фасад, вызывающие файлы не менялись, тексты для носителя совпадают побайтово |
| Р4 | Интерфейс: экраны работают через службы, а не через контейнер напрямую | `gui/**` | **отложена сознательно** 16.09.2026. Замеры: `gui/` — 8457 строк, крупнейший файл `config_wizard.py` (1738) состоит из регулярных троек «построить шаг / сохранить шаг / проверить шаг», 158 обращений к виджетам и ровно **два** обращения к контейнеру. Спутанной логики, ради которой заводят слой служб, там нет; правка тронула бы двенадцать экранов сразу, а принять её можно только на стенде — тесты интерфейса на маке не гоняются. Цена выше пользы: оба дефекта, ради которых затеян 1.2.0, жили в пути записи носителя |
| Р5 | Документация: README и PLAN сверить с кодом после Р1–Р4 | `README.md`, `docs/*` | **имена файлов сверены** 16.09.2026: дерево в README (пакет отзыва, `backends/constants.py`, `backends/text/`), путь к отзыву в документе выпуска. Остальное — после того, как код перестанет меняться. Упоминания `install/revocation.py` в этом файле исторические (замер «до» и цель зоны) и правке не подлежат |

Р5 идёт последним и не параллелится: он сверяет то, что сделали остальные.

## Решения

| Решение | Почему |
|---|---|
| Сначала выпуск 1.1.0, потом рефакторинг | Тег встаёт на состояние, проверенное живьём; перетряска кода не рискует уже подтверждённым поведением |
| Тесты — опора, а не предмет правки | Если правка ломает тест, вопрос к правке. Менять тест можно, только когда меняется договор, и это записывается сюда |
| Живые прогоны после каждой зоны, а не в конце | Дефекты этого проекта видны только загрузкой; накопить пять зон и искать, какая из них сломала носитель, — дороже |

## Допущения

- Стенд остаётся прежним: файл-образ через `losetup`, гость QEMU, сервер отзыва
  `test.nonkvn.ru`.
- Настоящей флешки и машины РЕД ОС по-прежнему нет.

## Открытые вопросы

- Нужен ли отдельный слой «политика киоска» или он остаётся частью бэкендов.
- Что делать с `POA_ALLOW_NON_REMOVABLE`: превращать в режим «развернуть в
  файл-образ» сейчас или после рефакторинга.

## Подводные камни

- **Киоск настраивается при сборке дистрибутива, а не при развёртывании.**
  Правку киоска нельзя проверить переразвёртыванием — нужна пересборка (~15
  минут).
- **Два пути записи носителя.** Любая правка, затрагивающая файлы носителя,
  должна проверяться обоими путями: установка с образа и развёртывание.
- **ID носителя содержит дефис.** Всё, что разбирает идентификаторы строками,
  обязано это учитывать — именно здесь уже был дефект.
