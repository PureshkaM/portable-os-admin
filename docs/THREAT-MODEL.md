# Модель угроз безопасности информации: portable-os-admin, LIVE-2.0

Типовая модель угроз решения для организации защищённого удалённого доступа сотрудников к их
рабочим местам с переносного носителя (флешка или токен), включая сервер доступа и программу
администратора. Составлена 01.10.2026, согласована с Максимом в тот же день.

Соседние документы: [`LIVE-2.0.md`](LIVE-2.0.md) — устройство решения и этапы работ,
[`../README.md`](../README.md) — справочник по программе.

## 1. Общие положения

### 1.1. Основа

- **Методика оценки угроз безопасности информации**, утверждена ФСТЭК России 05.02.2021. На
  01.10.2026 действует, новой редакции нет.
- **Приказ ФСТЭК России №117** (заменил приказ №17 с 01.03.2026) — требует моделировать угрозы
  по Методике с учётом БДУ. Меры защиты в этой модели названы по его группам.
- **Банк данных угроз ФСТЭК России (БДУ), новый раздел угроз** (`bdu.fstec.ru/threat-section`).
  Справочники выгружены 01.10.2026 через API сайта:
  - 11 обобщённых угроз УБИ.1–УБИ.11 группы «Информационные системы» (группа «Искусственный
    интеллект» к решению неприменима);
  - 12 объектов воздействия О.1–О.12 и 84 компонента К.x.x.x;
  - 182 способа реализации СП.1–СП.26;
  - 4 уровня возможностей нарушителя В.1–В.4;
  - 52 негативных последствия Н.1–Н.52;
  - 338 мер защиты в 17 группах.
- **Прежний каталог угроз БДУ** (`thrlist.xlsx`): УБИ.001–УБИ.227, 222 опубликованы, 5 в
  архиве, последние добавлены в июне 2025 (УБИ.223–227, контейнеры). Даётся перекрёстными
  ссылками: многие проверяющие продолжают работать по нему.

### 1.2. Статус документа

Это **типовая модель поставщика**. Она описывает угрозы самому решению. Оператор (ГИС, ИСПДн,
значимый объект КИИ) дополняет её своими негативными последствиями, классом или категорией
системы и средой развёртывания: облако, виртуализация, сегментация сети компании.

### 1.3. Условные обозначения

| Запись | Значение |
|---|---|
| УБИ.1 … УБИ.11 | угроза нового раздела БДУ |
| УБИ.067 (три цифры) | угроза прежнего каталога БДУ |
| О.x, К.x.x.x, СП.x.y, В.x, Н.x | объект, компонент, способ реализации, возможности нарушителя, негативное последствие по справочникам БДУ |
| ИАФ, УПД, ОПС, ЗНИ, АУД, АВЗ, СОВ, ОЦЛ, ОДТ, ЗТС, ЗИС, УКФ, ОПО, ПЛН, ДНС, ИНЦ, ИПО | группы мер защиты |
| Н-1 … Н-11 | нарушители этой модели (раздел 5) |
| A1 … V9 | сценарии этой модели (раздел 6) |
| Э… | этап работ из [`LIVE-2.0.md`](LIVE-2.0.md) |

Вывод по сценарию:

| Вывод | Значение |
|---|---|
| **нейтрализуется** | угроза актуальна, меры решения её закрывают для указанных возможностей нарушителя |
| **нейтрализуется обнаружением** | реализацию нельзя предотвратить, но её обнаруживают и на неё реагируют |
| **частично** | меры закрывают часть способов; остаток назван |
| **остаточный риск** | меры решения угрозу не закрывают; нужна организационная мера оператора или риск принимается |

Модель описывает **целевое состояние** после этапов LIVE-2.0. Меры, ещё не реализованные в
коде, помечены этапом, который их вводит (приложение Б).

## 2. Описание решения и границы моделирования

### 2.1. Назначение

Носитель — не рабочее место, а **дорога до рабочего места**. Сотрудник загружает с него чужой или
свой компьютер, поднимает сеть, получает у сервера доступа разрешение и сеансовый доступ к VPN
и подключается к своей машине в сети компании по RDP, VNC или SSH. Данные и работа остаются на
рабочем месте.

### 2.2. Состав

| Часть | Что это | Где |
|---|---|---|
| **Носитель-флешка** | загрузка (ESP), ядра слотов A/B, образы squashfs A/B с dm-verity, хранилище (LUKS), журналы (LUKS). Корень системы в RAM | у сотрудника |
| **Носитель-токен** (архитектура) | то же, загрузка на разделе «только чтение», ключ носителя в чипе | у сотрудника |
| **Система на носителе** | киоск MATE, `poa-accessd`, nftables, окно «Подключение», OpenVPN или ViPNet Client, xfreerdp, vncviewer, ssh в xterm, окно портала (WebKitGTK) | в RAM машины-хозяина |
| **Машина-хозяин** | чужой или свой компьютер, с которого загружается носитель. **Недоверенная среда** | где угодно |
| **Сервер доступа** | API v3 и проверка отзыва v2, онлайн-CA для VPN, CRL, раздача выпусков образа, журнал событий; PostgreSQL; один узел или кластер ≥3 (Patroni, etcd); «запечатан» | DMZ компании |
| **VPN-шлюз** | OpenVPN компании (или роль `gateway`), координатор ViPNet | DMZ компании |
| **Программа администратора** | сборка и подпись выпусков, выпуск носителей, управление сервером; контейнер с ключами | АРМ администратора |
| **Корневой ключ организации** | офлайн, в сейфе | вне сети |
| **Рабочие места** | Windows или Linux, физические или VDI | сеть компании |

### 2.3. Потоки

1. Носитель ↔ сервер доступа: TLS 1.3 с закреплённым ключом сервера, подпись носителя по
   одноразовому nonce. Проверка отзыва, активация, вход (TOTP и звено), выдача доступа, журнал,
   описатель сервера, выпуски образа.
2. Носитель ↔ VPN-шлюз: OpenVPN (TLS 1.3, `tls-crypt-v2`, сертификат на 24 часа) или ViPNet.
3. Носитель ↔ рабочее место внутри VPN: RDP (NLA), VNC (VeNCrypt X509Plain), SSH.
   Сертификаты и ключи хостов закреплены по профилю с сервера.
4. Шлюз → сервер доступа: CRL раз в минуту.
5. Программа администратора ↔ сервер: подписанные команды, распечатывание.
6. Носитель → проба портала: открытый HTTP, ничему не доверяется.

### 2.4. Границы

**Входит:** всё перечисленное в 2.2, кроме внутреннего устройства рабочих мест и сети компании за
шлюзом.

**Не входит, но учтено как требование к среде:** гипервизор и СХД, на которых работает сервер;
периметр компании (защита от DDoS); сегментация на внутреннем МЭ; защита самих рабочих мест.

## 6. Сценарии реализации угроз

Для каждого сценария указаны: суть, предпосылки, угрозы (новый раздел / каталог), нарушитель,
способы реализации, меры решения (с группами мер), остаточный риск и вывод.

### A. Носитель и машина-хозяин

#### A1. Кража или утрата носителя
- **Суть.** Носитель у постороннего; цель — ключ носителя, хранилище, вход.
- **Предпосылки.** Слабая фраза; отозвать не успели.
- **Угрозы.** УБИ.1, УБИ.2 / УБИ.156, УБИ.160, УБИ.067.
- **Нарушитель.** Н-4, Н-6. **СП.** СП.24.1, СП.17.6, СП.17.7.
- **Меры.** LUKS2 с argon2id; сгенерированная фраза 12 символов (≈70 бит); привязка к машинам;
  лимит попыток с кодом восстановления; TOTP на телефоне; отзыв со стиранием при выходе в сеть
  (ЗНИ, ИАФ, УПД).
- **Остаток.** Своя слабая фраза пользователя (разрешена от 10 символов).
- **Вывод.** Нейтрализуется.

#### A2. Копия носителя, подбор фразы и семя TOTP
- **Суть.** Сценарий, с которого начата LIVE-2.0: у злоумышленника снимок носителя и ссылка TOTP.
- **Предпосылки.** Носитель был у постороннего (курьер, бывший сотрудник); семя TOTP утекло.
- **Угрозы.** УБИ.2, УБИ.4 / УБИ.008, УБИ.074, УБИ.088.
- **Нарушитель.** Н-4, Н-7, Н-9. **СП.** СП.17.6, СП.17.7, СП.17.12.
- **Меры.** Сдвигающееся звено: сертификат выдаётся только после подтверждения записи нового
  звена; предъявление звена из истории — клон: блок носителя, его сертификаты в CRL, событие.
  У токена ключ в чипе не извлекается, клон невозможен (ИАФ, УПД, АУД).
- **Остаток.** Окно до следующего входа пользователя: злоумышленнику нужно успеть войти первым,
  подобрать фразу офлайн и знать пароль рабочего места.
- **Вывод.** Нейтрализуется обнаружением.

#### A3. Подмена загрузчика или проверяющей ступени для перехвата фразы
- **Суть.** Evil maid: носитель оставлен без присмотра, ступень на ESP заменена на крадущую фразу.
- **Предпосылки.** ESP флешки доступен на запись; Secure Boot машины выключен или доверяет
  чужому загрузчику.
- **Угрозы.** УБИ.3, УБИ.4 / УБИ.018, УБИ.145, УБИ.188.
- **Нарушитель.** Н-5. **СП.** СП.19.1, СП.19.3, СП.5.5.
- **Меры.** После разблокировки система сверяет ступень с хешем из подписанного выпуска и
  передаёт событие серверу, администратор отзывает носитель. У токена ступень на разделе «только
  чтение» (ОЦЛ, АУД, ИНЦ).
- **Остаток.** У флешки — только обнаружение и только после того, как фраза уже украдена.
- **Вывод.** Флешка — нейтрализуется обнаружением; токен — нейтрализуется.

#### A4. Офлайн-модификация образа или хранилища
- **Угрозы.** УБИ.3 / УБИ.023, УБИ.179. **Нарушитель.** Н-4, Н-5. **СП.** СП.19.4, СП.21.3.
- **Меры.** Образы подписаны, squashfs под dm-verity с корневым хешем из подписанного выпуска;
  хранилище в LUKS (ОЦЛ).
- **Вывод.** Нейтрализуется.

#### A5. Откат на старую уязвимую версию
- **Суть.** Подложить носителю старый, но подлинный выпуск с известной уязвимостью.
- **Угрозы.** УБИ.4, УБИ.9 / УБИ.192, УБИ.217. **Нарушитель.** Н-4, Н-1. **СП.** СП.4.10.
- **Меры.** `min_serial` в хранилище, сквозной `serial` выпусков; initramfs слота отказывает в
  загрузке при `serial < min_serial` (ОПО, ОЦЛ).
- **Вывод.** Нейтрализуется.

#### A6. Порча или износ носителя
- **Угрозы.** УБИ.8 / УБИ.155, УБИ.157, УБИ.182.
- **Меры.** Слоты A/B; dm-verity превращает молчаливую порчу в явную ошибку; откат на другой

### V. Виртуализация

Компоненты К.1.2.7 гипервизор и К.1.5.4 виртуальная машина. Способы СП.16.1, СП.16.3, СП.19.2.

#### V1. Снимок или резервная копия ВМ сервера
- **Суть.** Кто получил копию ВМ, тот пытается получить ключ CA, семена TOTP и базу со звеньями.

- **Нарушитель.** Н-11, Н-1. **СП.** СП.26.4, СП.26.5, СП.17.7.

#### V2. Администратор гипервизора
- **Суть.** Читает память ВМ, подключается к консоли, монтирует диск.
- **Угрозы.** УБИ.1, УБИ.2, УБИ.3 / УБИ.078, УБИ.119, УБИ.120.
- **Нарушитель.** Н-11. **СП.** СП.19.2, СП.16.1.

#### V3. Выход из соседней ВМ на гипервизор

- **Вывод.** Нейтрализуется.

- **Угрозы.** УБИ.8 / УБИ.108.

- **Угрозы.** УБИ.1, УБИ.2 / УБИ.115, УБИ.077, УБИ.078.

## 9. Что сознательно не нейтрализуется

- **Нарушитель В.4:** закладки в железе и прошивке машины-хозяина, недекларированные возможности.
- **Сертифицированные СКЗИ.** Криптография решения стандартная (TLS 1.3, Ed25519, X25519,
  AES-GCM, argon2id), но не сертифицирована ФСБ. Если оператору нужно СКЗИ класса КС1/КС2
  (приказ ФСБ №378), канал закрывается ViPNet, а модель дополняется требованиями к СКЗИ.
- **Визуальный и ручной вынос данных:** фото экрана, переписывание, текстовый буфер обмена.
- **Кейлоггер на машине-хозяине** — закрывается только вторыми факторами и регламентом.
- **Гипервизор сервера и снимки памяти** — только организационные меры оператора.
- **Компрометация корневого ключа** — восстановление только перевыпуском носителей.

## 10. Сопровождение модели

- Каждый этап LIVE-2.0, меняющий поверхность атаки, обновляет модель тем же коммитом.
- Раз в квартал — сверка с БДУ: новые угрозы обоих разделов и уязвимости по компонентам
  раздела 4 (ОС дистрибутивов, FreeRDP, TigerVNC, OpenSSH, OpenVPN, WebKitGTK, ViPNet Client,
  PostgreSQL, etcd, Patroni, Python).
- Каталог событий (приложение В) версионируется вместе с моделью: у каждого события есть
  сценарий, у каждого сценария, обнаружимого на носителе, — событие.

## Приложение В. Каталог событий журнала

### Правила

- До разблокировки LUKS в журнал не пишется ничего. Носитель отмечает **вход** (E01) и
  **выход** (E02). Сведения о том, что происходило до разблокировки, приходят параметрами входа
  из уже существующих данных: счётчика лимита попыток и состояния слотов.
- Журнал на носителе не перезаписывается, пока его не подтвердил сервер (подтверждение до `seq`).
  Выгрузка — при каждом входе в сеанс. При заполнении информационные события перестают
  писаться, критические и высокие идут в резерв.
- Сервер разворачивает коды в записи вида `ID_носителя: расшифровка кода`.
- Стирание по отзыву на носителе не журналируется: носитель затирается целиком. Факт фиксирует
  сервер — «отзыв доставлен носителю».
- То, что решает сервер (TOTP, клон, коды активации, отказы в сеансе), носитель не пишет.
- Уровни: **К** — критическое, **В** — высокое, **П** — предупреждение, **И** — информационное.
