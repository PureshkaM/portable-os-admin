# Токен на рабочем месте по USB/IP — прототип связки (SOLUTION.md 11.6–11.7)

Стендовый прототип, не код программы. Задача: токен сотрудника, подключённый к носителю,
попадает в сеанс xrdp на рабочем месте целиком (все механизмы ГОСТ), и пользоваться им
может только сеанс его владельца.

| Файл | Куда на рабочем месте | Что делает |
|---|---|---|
| `poa-token-attach` | `/usr/local/libexec/`, строка в `/etc/pam.d/xrdp-sesman`: `session optional pam_exec.so /usr/local/libexec/poa-token-attach` | при входе берёт с адреса носителя (`PAM_RHOST`) токены из белого списка по USB/IP, записывает появившиеся считыватели за пользователем в `/run/poa-token/map`; при выходе отсоединяет |
| `poa-token-owner` | `/usr/local/libexec/` | помощник polkit: владелец считывателя; запись действует, только пока её порт vhci занят по данным ядра |
| `49-poa-token.rules` | `/etc/polkit-1/rules.d/` | `access_card` — только владельцу считывателя (и локальному сеансу чужой — отказ); `access_pcsc` удалённому сеансу — только если у него есть свой токен; остальное — политика по умолчанию |
| `session-check.py` | только стенд | проверка изнутри сеанса: контекст PC/SC, `SCardConnect` к каждому считывателю, `--probe` — зонд ГОСТ |

На рабочем месте ещё нужны: пакет `usbip`, модуль `vhci-hcd` при загрузке
(`/etc/modules-load.d/`), доступ рабочего места к носителю на 3240/tcp внутри туннеля.
На носителе: `usbip-host` + `usbipd`, отдаётся только токен; **свой `pcscd` носителя
токен в это время не держит** — иначе две стороны тянут одно устройство.

Ограничение: закрытие сеанса PAM делает `xrdp-sesexec`, который живёт в cgroup сеанса —
при убийстве сеанса (`loginctl terminate-session`, сбой) отсоединения не будет. Поэтому
окончательно отпускает токен носитель (перестаёт отдавать по USB/IP при конце сеанса), а
записи без живого порта помощник не признаёт.
