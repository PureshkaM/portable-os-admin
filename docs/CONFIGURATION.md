# Конфигурация

Справочник по всем полям JSON-конфигурации сборки и выпуска носителя.
Значения по умолчанию взяты из `InstallConfig`; мастер нового профиля
использует ограниченный киоск MATE. Полнота справочника проверяется
`tests/test_config_reference.py`: тест обнаруживает пропущенные поля
и описания полей, которых больше нет в схеме.

[Обзор проекта](../README.md) · [Остальная документация](README.md)

## Что это за файл и где он лежит

Конфигурация — обычный JSON. Он хранится в контейнере администратора рядом с
записями о носителях; в интерфейсе им управляет экран «Конфигурации», а
последний шаг мастера показывает файл целиком и позволяет править его прямо
там.

Одна конфигурация описывает **одну устанавливаемую систему**: что за
дистрибутив, как разбит носитель, кто пользователь, что за режим работы. Её
можно применить к любому числу носителей.

### Почему свой формат, а не kickstart или preseed

Ни kickstart, ни preseed не выражают того, ради чего существует эта
программа: LUKS на переносном носителе с отдельными томами состояния и
журналов, коды восстановления, ограничения приложений киоска и отзыв
розданных флешек. К тому же общего формата на оба семейства нет — preseed и
kickstart несовместимы, а программа ставит и Debian, и РЕД ОС из одной
конфигурации.

Чтобы формат не превратился в «проверяется по нашим же выдуманным правилам»,
конфигурация **переводится в родной формат целевого дистрибутива и отдаётся
его штатному валидатору**:

| Семейство | Формат | Чем проверяется |
|---|---|---|
| Debian | preseed | `debconf-set-selections --checkonly` |
| РЕД ОС | kickstart | `pykickstart`, взятый **из самого устанавливаемого образа** |

Оговорка, которую стоит знать: **установка выполняется не этим файлом**.
Программа не запускает штатный установщик дистрибутива — она сама делает
`debootstrap` / `dnf --installroot`, разметку, шифрование и настройку.
Родной файл нужен для внешней проверки части параметров. Он не воспроизводит
всю текущую разметку v3 и путь загрузки носителя; перед отдельным применением
со штатным установщиком его нужно адаптировать.

### Проверка

Проверка включает два слоя:

1. **Внутренние правила** — то, чего не знает ни один внешний валидатор:
   что `/boot` обязан быть вне LUKS-тома, какие длины ключа принимает
   выбранный шифр, что имя запускателя киоска не содержит разделителей пути.
2. **Штатный валидатор дистрибутива** — из таблицы выше, если он доступен.

При отсутствии внешней утилиты приложение сообщает об ограничении проверки.
Статус `valid` в этом случае означает прохождение только внутренних правил.

Конфигурация со статусом `invalid` до установки не допускается. Со статусом
`unchecked` — тоже: собрать дистрибутив можно только из проверенной.
Внешняя проверка не подтверждает загрузку образа или действие всех ограничений:
для этого нужен отдельный прогон на Linux-стенде.

## Общие поля

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `name` | строка | — | Имя конфигурации. Используется как имя файла и показывается в списках. |
| `target_os` | строка | `debian` | Семейство: `debian`, `redos`. Определяет и способ установки, и родной формат для проверки. Другое значение отвергается. |
| `release` | строка | `""` | Выпуск: `trixie`, `8.0`. При установке с образа берётся из самого образа, а это значение служит для проверки совместимости. |
| `mirror` | строка | `""` | Адрес репозитория компании. При сборке он **заменяет** официальный репозиторий из образа как источник пакетов и обновлений; без образа — единственный источник. По этому же адресу работает браузер пакетов в мастере. |
| `network_packages` | булево | `true` | Брать ли при сборке пакеты и обновления из сети: из `mirror`, если задан, иначе из официального репозитория, записанного в образе. Базовая система ставится с образа, затем всё обновляется до актуальных версий. `false` — сборка только с образа, для изолированного контура. |
| `arch` | строка | `""` | Архитектура носителя: `amd64`/`x86_64`, `arm64`/`aarch64`. Пусто — как у машины, на которой идёт сборка. Чужая архитектура допускается, если ядро умеет исполнять её программы (`binfmt_misc` с флагом `F`); иначе установка отклоняется **до** стирания носителя. |
| `hostname` | строка | `portable-os` | Имя устанавливаемой системы в сети. Стоит менять: одинаковое имя у всех носителей организации мешает в сети и в журналах. |
| `profile` | строка | `console` | Для выдачи сотруднику требуется графический режим `kiosk`. Значение `console` сохраняется в прежних конфигурациях и автономных диагностических сборках. |
| `packages` | список строк | `[]` | Дополнительные пакеты, устанавливаемые после базовой системы. Имена — как в целевом дистрибутиве. |
| `system_tasks` | список строк | `[]` | Произвольные команды, выполняемые в chroot целевой системы в самом конце настройки. Запасной выход для того, что не выражается полями. Выполняются от root, ошибка прерывает установку. |
| `validation_status` | строка | `unchecked` | Результат последней проверки: `unchecked`, `valid`, `invalid`. Служебное поле результата проверки; вручную его задавать не следует. |
| `validation_errors` | список строк | `[]` | Что именно сказал валидатор. Тоже производное. |

## `disk` — размеры служебных разделов

В текущей схеме v3 пять разделов: ESP, `/boot`, зашифрованное состояние,
зашифрованные журналы и область общих образов A/B. Область образов занимает
остаток носителя; общий `rootfs.squashfs` не зашифрован и проверяется dm-verity
(механизмом контроля целостности блоков). Корень ОС собирается из общего
образа, индивидуального слоя носителя и временных изменений в RAM. Отдельного
раздела обмена нет.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `disk.esp_partition_mb` | целое | `512` | Раздел EFI. Не меньше 128 МБ: сюда ставится загрузчик. |
| `disk.boot_partition_mb` | целое | `1024` | `/boot`, **незашифрованный**: GRUB должен прочитать ядро и initramfs до разблокировки LUKS. Хранит загрузочные файлы обоих слотов (`slot-a/`, `slot-b/`) и initrd носителя. Не меньше 512 МБ; фактический размер должен вмещать оба комплекта. |
| `disk.state_partition_mb` | целое | `1024` | Зашифрованный том (LUKS): слой носителя (то, что пишется при записи: ключи, настройки, файлы администратора) и состояние между сеансами (сети, `/var/lib/poa`). Системы в нём нет — она в образе на разделе образов, поэтому размер фиксированный. Не меньше 512 МБ. Раздел образов (`POA_IMAGES`, два слота с деревом dm-verity) занимает остаток носителя; носитель — от 16 ГБ. |
| `disk.system_image` | булево | `true` | Наследуемое поле совместимости. В схеме v3 система всегда разворачивается сжатым образом под overlay (слоем файлов поверх общего образа); значение `false` больше не переключает носитель на распакованное дерево. |
| `disk.log_partition_mb` | целое | `512` | Том журналов, монтируется на `/var/log`. Открывается ключом администратора, поэтому журналы читаются без парольной фразы пользователя. Не меньше 64 МБ. |
| `disk.exchange_partition_mb` | целое | `0` | Наследуемое поле совместимости: в разметке v3 раздела обмена нет. Файлы администратора, положенные при записи, лежат в слое носителя и видны в `/mnt/exchange` только для чтения, без запуска. Поле читается у старых конфигураций и ни на что не влияет. |

Фиксированные размеры и необходимое место проверяются до стирания.
Указанный минимум емкости не гарантирует, что поместится любой образ:
для обновления нужны оба слота образов и оба комплекта загрузочных файлов.

## `luks` и `machine_binding` — шифрование и привязка носителя

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `machine_binding.slots` | целое | `5` | Сколько разных машин носитель запомнит. На незнакомой машине система спрашивает подтверждение и занимает слот; когда занят последний, регистрационный ключ LUKS уничтожается, и на незарегистрированной машине том больше не открывается — ключа для неё в заголовке нет. `0` — ограничения нет. Отпечаток считается по плате и процессору, поэтому док-станция или USB-сетевая карта его не меняют. Оставшиеся keyslot заголовка отдаются под одноразовые коды восстановления: чем меньше машин, тем больше кодов. |
| `luks.cipher` | строка | `aes-xts-plain64` | Шифр. То же, что используют штатные установщики Debian и RHEL. |
| `luks.key_size_bits` | целое | `512` | Длина ключа. В режиме XTS ключ делится пополам, поэтому 512 бит — это AES-256. Допустимые значения зависят от шифра и проверяются. |
| `luks.kdf` | строка | `argon2id` | Функция выведения ключа из парольной фразы. |
| `luks.failed_attempts_limit` | целое | `5` | Сколько раз при загрузке можно ошибиться паролем, прежде чем запустится восстановление. Попадает в `crypttab` носителя как `tries=`. Перебору мешает слабо: он останавливает подбор только через загрузку носителя, а тот, у кого носитель в руках, снимет образ заголовка и будет перебирать у себя, где счётчика нет. |
| `luks.min_passphrase_length` | целое | `10` | Минимальная длина **своей** фразы LUKS. По умолчанию мастер выпуска генерирует фразу сам: 12 случайных латинских знаков без похожих (≈70 бит). Оценка в битах верна только для сгенерированной фразы; стойкость придуманной человеком фразы такой длины не гарантируется, поэтому своя фраза допускается с предупреждением. |

Стоимость `argon2id` по памяти **не настраивается** и ограничена 256 МиБ.
Без ограничения `cryptsetup` подбирает ее под машину-изготовитель и сохраняет
в заголовке: носитель, созданный на машине с 32 ГБ, может не открыться на
компьютере с меньшим объемом памяти.

Допустимые KDF (функции получения ключа из фразы): `argon2id`, `argon2i`,
`pbkdf2`. Поддерживаются шифры `aes-xts-plain64`, `serpent-xts-plain64`,
`twofish-xts-plain64` с ключами 512 или 256 бит и `aes-cbc-essiv:sha256`
с ключами 256, 192 или 128 бит. Лимит штатных попыток ввода — от 1 до 10.

Привязка по DMI/CPU не является неизвлекаемым аппаратным секретом. Пока
машинные слоты свободны, действует регистрационный слот с обычной фразой;
он удаляется после заполнения лимита машин.

## `account` — учётная запись в устанавливаемой системе

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `account.username` | строка | `user` | Имя пользователя. Строчные латинские буквы, цифры, подчёркивание, дефис; не начинается с цифры. |
| `account.full_name` | строка | `""` | Полное имя (поле GECOS). Необязательно. |
| `account.sudo` | булево | `false` | Давать ли право администрирования. В режиме киоска включать не следует: это обходит все ограничения. |
| `account.shell` | строка | `/bin/bash` | Оболочка входа. |
| `account.min_password_length` | целое | `8` | Проверяемый минимум длины пароля учетной записи, не менее 8. Штатный пользователь создается с заблокированным паролем (`passwd -l`); поле не включает парольный вход и не меняет длину фразы LUKS. |

## `localisation` — язык, раскладка, часовой пояс

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `localisation.locale` | строка | `en_US.UTF-8` | Значение `LANG`. В Debian локаль дополнительно собирается `locale-gen`; в РЕД ОС приходит готовой. Локаль, которой нет в системе, молча откатывается к `C` — то есть заданный язык просто не работает. |
| `localisation.keymap` | строка | `us` | Раскладка **текстовой** консоли (`/etc/vconsole.conf`). |
| `localisation.x11_layouts` | строка | `""` | Раскладки графического сеанса через запятую: `us,ru`. Пусто — берётся раскладка консоли. Задаётся отдельно, потому что графический сеанс не читает `vconsole.conf`, и система с русской консолью и английским рабочим столом — обычный результат того, что задали только `keymap`. |
| `localisation.x11_options` | строка | `""` | Как переключать раскладки: `grp:alt_shift_toggle` и подобное. Пусто — переключателя нет. |
| `localisation.timezone` | строка | `UTC` | Пояс из базы tzdata: `Europe/Moscow`, `Asia/Yekaterinburg`. Неверное имя оставит систему без `/etc/localtime`. |
| `localisation.hardware_clock_utc` | булево | `true` | Считать ли аппаратные часы идущими по UTC. Ставить `false` стоит только если носитель приносят на машину, где рядом стоит Windows: она держит часы по местному времени. |

## `boot` — загрузчик и параметры ядра

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `boot.menu_timeout_seconds` | целое | `5` | Сколько секунд показывать меню загрузчика. `0` — не показывать. |
| `boot.kernel_parameters` | строка | `""` | Дополнительные параметры ядра. Добавляются к тем, что программа задаёт сама (корень, разблокировка тома): их она не отдаёт, потому что от них зависит, загрузится ли носитель вообще. |
| `boot.quiet` | булево | `false` | Тихая загрузка (`quiet`). Заставка (`splash` у Debian, `rhgb` у РЕД ОС) от этого поля не зависит и включена всегда: ею носитель спрашивает пароль, привязку к машине и код восстановления. |
| `boot.verbose` | булево | `false` | Подробная загрузка для разбора неполадок: снимает `quiet`, добавляет `systemd.show_status=1`. Заставку не снимает — сообщения видны по Esc поверх неё и в журнале на томе журналов. |
| `boot.serial_console` | булево | `false` | Дублировать вывод загрузки в последовательный порт — для стенда. Добавляет `console=ttyS0,115200 console=tty0`: экран остаётся главной консолью, поэтому запрос пароля не уходит в порт. Вписывать `console=` в `kernel_parameters` руками не нужно — валидатор предупредит. Только в экспертном режиме мастера. |

## `network` — сеть устанавливаемой системы

Пустые поля означают «как решит NetworkManager», то есть DHCP на всех
интерфейсах. Для переносного носителя это правильное умолчание: он не знает,
в какой сети окажется. Статический адрес имеет смысл, только когда носитель
привязан к известному месту.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `network.method` | строка | `dhcp` | `dhcp` или `static`. При `dhcp` не пишется ничего. |
| `network.address` | строка | `""` | Адрес с длиной префикса: `192.168.1.50/24`. Только при `static`. |
| `network.gateway` | строка | `""` | Шлюз по умолчанию. |
| `network.nameservers` | строка | `""` | Серверы имён через запятую. |
| `network.interface` | строка | `""` | Интерфейс, к которому относится настройка. Пусто — любой проводной. |

## `firewall` — брандмауэр и мандатный контроль доступа

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `firewall.enabled` | булево | `true` | Включать ли службу брандмауэра дистрибутива. В семействе, где её нет, поле молча не действует. |
| `firewall.open_ports` | список строк | `[]` | Открытые порты: `22/tcp`. Пусто — политика дистрибутива по умолчанию. Применяется там, где у семейства есть штатная служба брандмауэра: в РЕД ОС это firewalld, в Debian такой службы по умолчанию нет и поле не действует. |
| `firewall.selinux` | строка | `enforcing` | Режим SELinux в RHEL-семействе: `enforcing`, `permissive`, `disabled`. Файл читается ядром при загрузке, поэтому задать режим можно только здесь. В Debian не действует: там AppArmor. |

## `extra_users` — дополнительные учётные записи

Список объектов. Пароль ни одной из них не задается: учетные записи
создаются с заблокированным паролем. На носителе сотрудника входящий SSH отключён.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `extra_users` | список объектов | `[]` | Каждый объект: `username`, `full_name`, `sudo`, `shell`, `groups` (через запятую), `ssh_keys` (список открытых ключей). |

## `package_sets` — чем заменить наборы пакетов

Пустой список означает «как решит программа»: для РЕД ОС базовый состав
читается из `comps.xml` самого образа, остальные наборы — списки, подобранные
вручную. Подобраны они не случайно: в набор графики нарочно не входят
терминал, системный монитор и центр управления — их отсутствие и есть самое
сильное ограничение режима киоска.

Заданный список **заменяет** набор целиком. Чтобы дополнить, а не заменить,
есть `packages`.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `package_sets.base` | список строк | `[]` | Базовая система. Слишком короткий список даёт корень, в котором нечему работать, и выяснится это через полчаса установки. |
| `package_sets.boot` | список строк | `[]` | Ядро, загрузчик, генератор initramfs, cryptsetup. Без них носитель не загрузится, поэтому заменять стоит, только зная чем. |
| `package_sets.desktop` | список строк | `[]` | Графическое окружение режима киоска. |
| `package_sets.kiosk` | список строк | `[]` | Дополнения самого режима киоска поверх графики. |
| `package_sets.exclude` | список строк | `[]` | Что выкинуть из любого набора, включая вычисленный из образа. Работает и когда набор не переопределён — способ убрать один пакет, не переписывая весь список. |

## `remote_access` в прежних конфигурациях

Для выдачи сотруднику `remote_access.enabled` должен иметь значение `false`.
Мастер сохраняет графический киоск с отключённым входящим SSH. Прежние
консольные образы и киоски с SSH требуется пересобрать перед выдачей или обновлением.
Поля `remote_access.method`, `remote_access.port` и `remote_access.params` сохраняют прежние
параметры обслуживания. В графическом профиле они не включают службу.
На компьютере администратора и тестовых ВМ SSH настраивает их владелец.

## `kiosk` — режим киоска

Действует, когда `kiosk.enabled` истинно; тогда `profile` становится `kiosk`.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `kiosk.enabled` | булево | `false` | Включает режим: урезанный рабочий стол вместо текстового входа. |
| `kiosk.desktop_environment` | строка | `mate` | Рабочая среда; допустимо только `mate`. Конфигурация со значением `kde` при открытии переводится на MATE и требует повторной проверки; наследуемый ключ `session_type` отбрасывается. MATE работает под X11. |
| `kiosk.hidden_launchers` | список строк | `[]` | Запускатели, которые администратор снял вручную. Доступные приложения определяются установленными пакетами; этот список убирает лишние запускатели, если пакет поставил несколько. Имена desktop-записей без `.desktop`; разделители пути запрещены. |
| `kiosk.allowed_settings` | список строк | `[]` | Сохраненные категории настроек: `network` — сеть, `sound` — звук, `datetime` — дата и время, `localisation` — язык и форматы, `keyboard` — раскладка. В текущем киоске MATE поле не применяется: центр управления в него не устанавливается. Изменение списка не открывает эти настройки пользователю. |
| `kiosk.autostart_app` | строка | `""` | Приложение, запускаемое сразу после входа. Пусто — не запускать ничего. |
| `kiosk.screen_blank_minutes` | целое | `0` | Через сколько минут гасить экран. `0` — не гасить. |
| `kiosk.allow_shutdown` | булево | `true` | Разрешать ли выключение и перезагрузку из сеанса. |
| `kiosk.allow_removable_media` | булево | `false` | Разрешать ли автомонтирование сменных носителей. По умолчанию запрещено: иначе пользователь получает доступ к произвольным файлам на подключенных устройствах. |
| `kiosk.firejail` | булево | `false` | Запускать ли разрешённые приложения в песочнице firejail. Пакет ставится дополнительно и может отсутствовать в образе. |
| `kiosk.firejail_options` | строка | `""` | Дополнительные параметры firejail. |

## `revocation` — отзыв носителя

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `revocation.enabled` | булево | `false` | Включать ли серверную проверку состояния после загрузки, при появлении сети и далее примерно раз в пять минут. В киоске приложения закрыты до первого подписанного `ok` текущей загрузки; подписанный ответ `revoked` запускает необратимое уничтожение ключей и данных носителя. Этот же переключатель включает клиент серверного доступа. Физическое стирание всех ячеек flash не гарантируется. |
| `revocation.url` | строка | пусто | Адрес ресурса, у которого носитель спрашивает своё состояние. Здесь он не набирается руками: приложение подставляет адрес, с которым контейнер познакомился («Обслуживание» → «Подключиться»), — иначе носители одной организации разошлись бы по разным адресам из-за опечатки в одной конфигурации. **Ресурс должен быть общедоступным**, и это не недосмотр: проверка обязана срабатывать раньше, чем носитель дотянется до внутренней сети. Только `https://` — подпись защищает ответ от подмены, но по открытому каналу видно, какие носители у организации есть и когда они включаются. |
| `revocation.timeout_seconds` | целое | `10` | Сколько секунд ждать сетевого ответа в одном проходе проверки. Отсутствие ответа не вызывает стирание и сохраняет прежний статус: до первого `ok` приложения киоска остаются закрыты, после него авторизация текущей загрузки сохраняется. Предельный срок автономного допуска этим полем не задается. |

## Чего пока нельзя задать

Эти свойства не выражаются отдельными полями конфигурации:

- **Файловые системы разделов**: ext4, кроме ESP с FAT32; общий образ ОС
  хранится в squashfs. Другие файловые системы требуют изменения
  установщика и загрузочной среды.
- **Штатный брандмауэр Debian**: `firewall.enabled` и `firewall.open_ports`
  не настраивают его в этом семействе. Клиент доступа устанавливает
  собственный экран nftables независимо от этих полей.
- **Назначения рабочих мест, VPN-шлюзы и группы доступа**: задаются отдельно
  через сервер доступа, а не в JSON-конфигурации сборки.
- **Пакетное обновление работающего носителя**: текущая схема обновляет общий
  образ выпуском целиком; отдельного поля пакетного автообновления нет.

Для дополнительных настроек целевой ОС есть `system_tasks`: команды
выполняются от root в chroot (каталоге, который команда видит как корень ОС).
Они могут изменить или ослабить штатные ограничения; внешняя проверка
конфигурации не доказывает безопасность произвольной команды. Настройки
сервера доступа и протокол загрузки таким способом автоматически не меняются.
