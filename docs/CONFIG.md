# Файл конфигурации установки

Справочник по формату. Здесь перечислено **всё**, что можно задать, что
означает каждое поле и что будет при неверном значении.

Полнота этого документа проверяется тестом: если в программе появится поле,
не описанное здесь, тест упадёт (`tests/test_config_reference.py`). Поэтому
список не может незаметно устареть.

---

## Что это за файл и где он лежит

Конфигурация — обычный JSON. Он хранится в контейнере администратора рядом с
записями о носителях; в интерфейсе им управляет экран «Конфигурации», а
последний шаг мастера показывает файл целиком и позволяет править его прямо
там.

Одна конфигурация описывает **одну устанавливаемую систему**: что за
дистрибутив, как разбит носитель, кто пользователь, что за режим работы. Её
можно применить к любому числу носителей.

### Почему свой формат, а не kickstart или preseed

Ни kickstart, ни preseed не выражают того, ради чего существует эта
программа: LUKS на переносном носителе с отдельными томами журналов и обмена,
код восстановления, белый список приложений киоска, автообновление парка
розданных флешек. К тому же общего формата на оба семейства нет — preseed и
kickstart несовместимы, а программа ставит и Debian, и РЕД ОС из одной
конфигурации.

Чтобы формат не превратился в «проверяется по нашим же выдуманным правилам»,
конфигурация **переводится в родной формат целевого дистрибутива и отдаётся
его штатному валидатору**:

| Семейство | Формат | Чем проверяется |
|---|---|---|
| Debian, Astra | preseed | `debconf-set-selections --checkonly` |
| РЕД ОС | kickstart | `pykickstart`, взятый **из самого устанавливаемого образа** |

Оговорка, которую стоит знать: **установка выполняется не этим файлом**.
Программа не запускает штатный установщик дистрибутива — она сама делает
`debootstrap` / `dnf --installroot`, разметку, шифрование и настройку.
Родной файл нужен как внешняя, не наша проверка, и как артефакт, который
можно отдать штатному установщику.

### Проверка

Проверок две, и обе обязательны:

1. **Внутренние правила** — то, чего не знает ни один внешний валидатор:
   что `/boot` обязан быть вне LUKS-тома, какие длины ключа принимает
   выбранный шифр, что имя приложения киоска не содержит разделителей пути.
2. **Штатный валидатор дистрибутива** — из таблицы выше.

Конфигурация со статусом `invalid` до установки не допускается. Со статусом
`unchecked` — тоже: собрать дистрибутив можно только из проверенной.

## Общие поля

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `name` | строка | — | Имя конфигурации. Используется как имя файла и показывается в списках. |
| `target_os` | строка | `debian` | Семейство: `debian`, `astra`, `redos`. Определяет и способ установки, и родной формат для проверки. Другое значение отвергается. |
| `release` | строка | `""` | Выпуск: `trixie`, `8.0`. При установке с образа берётся из самого образа, а это значение служит для проверки совместимости. |
| `mirror` | строка | `""` | Адрес сетевого репозитория. Используется **только** если образ не задан: установка с локального образа — основной путь, и молча подменять его сетью нельзя. Также по этому адресу работает браузер пакетов в мастере. |
| `arch` | строка | `""` | Архитектура носителя: `amd64`, `arm64`. Пусто — как у машины, на которой идёт сборка. Чужая архитектура допускается, если ядро умеет исполнять её программы (`binfmt_misc` с флагом `F`); иначе установка отклоняется **до** стирания носителя. |
| `hostname` | строка | `portable-os` | Имя устанавливаемой системы в сети. Стоит менять: одинаковое имя у всех носителей организации мешает в сети и в журналах. |
| `profile` | строка | `console` | Режим работы: `console` — текстовый вход без графики, `kiosk` — урезанный рабочий стол. Поле производное: меняется вместе с `kiosk.enabled`. |
| `packages` | список строк | `[]` | Дополнительные пакеты, устанавливаемые после базовой системы. Имена — как в целевом дистрибутиве. |
| `system_tasks` | список строк | `[]` | Произвольные команды, выполняемые в chroot целевой системы в самом конце настройки. Запасной выход для того, что не выражается полями. Выполняются от root, ошибка прерывает установку. |
| `validation_status` | строка | `unchecked` | Результат последней проверки: `unchecked`, `valid`, `invalid`. Поле **производное** — задавать вручную бессмысленно, программа перезапишет. |
| `validation_errors` | список строк | `[]` | Что именно сказал валидатор. Тоже производное. |

## `disk` — размеры служебных разделов

Носитель размечается на пять разделов: ESP, `/boot`, системный (шифрованный),
журналы (шифрованный), обмен (шифрованный). Системный занимает всё
оставшееся место, поэтому его размер не задаётся.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `disk.esp_partition_mb` | целое | `512` | Раздел EFI. Не меньше 128 МБ: сюда ставится загрузчик. |
| `disk.boot_partition_mb` | целое | `1024` | `/boot`, **незашифрованный** — иначе прошивке нечего загружать. Хранит ядро и initramfs. Не меньше 512 МБ. |
| `disk.log_partition_mb` | целое | `512` | Том журналов, монтируется на `/var/log`. Открывается ключом администратора, поэтому журналы читаются без парольной фразы пользователя. Не меньше 64 МБ. |
| `disk.exchange_partition_mb` | целое | `2048` | Том обмена, монтируется на `/mnt/exchange`. Единственное место, куда пользователь носителя может положить свои файлы. В режиме киоска монтируется с `noexec`. Не меньше 64 МБ. |

Если сумма разделов больше носителя, установка отклоняется до стирания.

## `luks` — шифрование системного раздела

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `luks.cipher` | строка | `aes-xts-plain64` | Шифр. То же, что используют штатные установщики Debian и RHEL. |
| `luks.key_size_bits` | целое | `512` | Длина ключа. В режиме XTS ключ делится пополам, поэтому 512 бит — это AES-256. Допустимые значения зависят от шифра и проверяются. |
| `luks.kdf` | строка | `argon2id` | Функция выведения ключа из парольной фразы. |
| `luks.failed_attempts_limit` | целое | `5` | Сколько раз при загрузке можно ошибиться паролем, прежде чем запустится восстановление. Попадает в `crypttab` носителя как `tries=`. |

Стоимость `argon2id` по памяти **не настраивается** и ограничена 256 МиБ.
Причина: `cryptsetup` подбирает её под машину-изготовитель и записывает в
заголовок навсегда, а носитель переносной — собранный на машине с 32 ГБ он
может не открыться там, куда его принесли.

## `account` — учётная запись в устанавливаемой системе

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `account.username` | строка | `user` | Имя пользователя. Строчные латинские буквы, цифры, подчёркивание, дефис; не начинается с цифры. |
| `account.full_name` | строка | `""` | Полное имя (поле GECOS). Необязательно. |
| `account.sudo` | булево | `false` | Давать ли право администрирования. В режиме киоска включать не следует: это обходит все ограничения. |
| `account.shell` | строка | `/bin/bash` | Оболочка входа. |
| `account.min_password_length` | целое | `8` | Минимальная длина пароля. Влияет на настройку системы, но **не** на парольную фразу LUKS: у учётной записи пароль снят (`passwd -l`), и единственный секрет носителя — фраза LUKS. |

## `localisation` — язык, раскладка, часовой пояс

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `localisation.locale` | строка | `en_US.UTF-8` | Значение `LANG`. В Debian локаль дополнительно собирается `locale-gen`; в РЕД ОС приходит готовой. Локаль, которой нет в системе, молча откатывается к `C` — то есть заданный язык просто не работает. |
| `localisation.keymap` | строка | `us` | Раскладка **текстовой** консоли (`/etc/vconsole.conf`). |
| `localisation.x11_layouts` | строка | `""` | Раскладки графического сеанса через запятую: `us,ru`. Пусто — берётся раскладка консоли. Задаётся отдельно, потому что графический сеанс не читает `vconsole.conf`, и система с русской консолью и английским рабочим столом — обычный результат того, что задали только `keymap`. |
| `localisation.x11_options` | строка | `""` | Как переключать раскладки: `grp:alt_shift_toggle` и подобное. Пусто — переключателя нет. |
| `localisation.timezone` | строка | `UTC` | Пояс из базы tzdata: `Europe/Moscow`, `Asia/Yekaterinburg`. Неверное имя оставит систему без `/etc/localtime`. |
| `localisation.hardware_clock_utc` | булево | `true` | Считать ли аппаратные часы идущими по UTC. Ставить `false` стоит только если носитель приносят на машину, где рядом стоит Windows: она держит часы по местному времени. |

## `remote_access` — удалённый доступ к установленной системе

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `remote_access.enabled` | булево | `false` | Включать ли доступ. В режиме киоска это единственный способ попасть в систему для проверки: текстовые консоли там отключены. |
| `remote_access.method` | строка | `openssh` | Способ. Поддержан `openssh`. |
| `remote_access.port` | целое | `22` | Порт SSH. |
| `remote_access.params` | объект | `{}` | Дополнительные параметры способа. Содержимое зависит от `method`. |

## `kiosk` — режим киоска

Действует, когда `kiosk.enabled` истинно; тогда `profile` становится `kiosk`.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `kiosk.enabled` | булево | `false` | Включает режим: урезанный рабочий стол вместо текстового входа. |
| `kiosk.desktop_environment` | строка | `mate` | Рабочая среда: `mate` или `kde`. KDE ограничивает строже — запреты проверяют сами приложения, — но тяжелее и дольше ставится. |
| `kiosk.session_type` | строка | `x11` | Графический протокол: `x11` или `wayland`. Wayland доступен только для KDE. В образе РЕД ОС Wayland-сеанса Plasma нет. |
| `kiosk.allowed_apps` | список строк | `[]` | Разрешённые приложения — имена desktop-записей без `.desktop`: `mate-calc`, `firefox-esr`. Всё остальное скрывается из меню и с рабочего стола. Разделители пути запрещены: имя подставляется в команду внутри системы. |
| `kiosk.autostart_app` | строка | `""` | Приложение, запускаемое сразу после входа. Пусто — не запускать ничего. |
| `kiosk.screen_blank_minutes` | целое | `0` | Через сколько минут гасить экран. `0` — не гасить. |
| `kiosk.allow_shutdown` | булево | `true` | Разрешать ли выключение и перезагрузку из сеанса. |
| `kiosk.allow_removable_media` | булево | `false` | Разрешать ли автомонтирование сменных носителей. По умолчанию запрещено: иначе принесённая флешка обходит раздел обмена с его `noexec`. |
| `kiosk.firejail` | булево | `false` | Запускать ли разрешённые приложения в песочнице firejail. Пакет ставится дополнительно и может отсутствовать в образе. |
| `kiosk.firejail_options` | строка | `""` | Дополнительные параметры firejail. |

## `auto_update` — самообновление носителя

Для парка розданных флешек, которые не собрать обратно.

| Поле | Тип | Умолчание | Что делает |
|---|---|---|---|
| `auto_update.enabled` | булево | `false` | Включать ли обновление по расписанию. |
| `auto_update.include_kernel` | булево | `true` | Обновлять ли ядро и загрузочные пакеты. Выключение оставляет систему на прежнем ядре — иногда это осознанный выбор для парка одинаковых машин. |
| `auto_update.delay_minutes` | целое | `5` | Задержка после загрузки перед проверкой обновлений. Нужна, чтобы обновление не начиналось раньше, чем поднимется сеть. |

## Пример: киоск РЕД ОС с KDE

```json
{
  "name": "kiosk-redos-kde",
  "target_os": "redos",
  "release": "8.0",
  "arch": "amd64",
  "hostname": "kiosk-07",
  "profile": "kiosk",
  "localisation": {
    "locale": "ru_RU.UTF-8",
    "keymap": "ru",
    "x11_layouts": "us,ru",
    "x11_options": "grp:alt_shift_toggle",
    "timezone": "Europe/Moscow"
  },
  "account": {"username": "kiosk", "full_name": "Kiosk user"},
  "kiosk": {
    "enabled": true,
    "desktop_environment": "kde",
    "session_type": "x11",
    "allowed_apps": ["mate-calc", "atril"]
  },
  "packages": ["mate-calc", "atril"],
  "disk": {"exchange_partition_mb": 4096}
}
```

Пропущенные поля берут значения по умолчанию из таблиц выше.

## Чего пока нельзя задать

Честный список того, что зашито в программе и в конфигурации не выражается.
Каждый пункт — задача, а не решение:

- состав базовой системы, графического окружения и киоска (наборы пакетов
  выбираются бэкендом; для РЕД ОС базовый состав читается из `comps.xml`
  самого образа);
- какие службы включаются и маскируются;
- настройки сети;
- параметры ядра в `grub.cfg`;
- файловые системы разделов (везде ext4, ESP — FAT32);
- больше одной учётной записи;
- брандмауэр и SELinux.

Пока поля нет, обходной путь — `system_tasks`: команды выполняются в chroot
целевой системы и могут сделать всё, что сделал бы администратор руками.
