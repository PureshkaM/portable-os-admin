# portable-os-admin

Административное приложение для создания и администрирования переносной
операционной системы на внешнем LUKS-зашифрованном носителе — реализация
дипломного проекта.

Полное соответствие требованиям проекта и статус реализации —
в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что делает приложение

- Хранит сведения о созданных переносных системах и данные восстановления
  в зашифрованном **контейнере администратора** (AES-256-GCM, ключ — через
  scrypt), доступном только в рамках **сеанса администратора**.
- Создаёт, редактирует и проверяет **файл конфигурации установки**
  (аналог Kickstart-конфигурации): разметка носителя, параметры LUKS,
  учётная запись пользователя, системные задачи, удалённый доступ.
- Устанавливает ОС на внешний носитель: размечает диск (загрузочный раздел,
  LUKS-раздел, раздел логов, раздел обмена), создаёт LUKS2-раздел с
  пользовательским и recovery-keyslot'ом, разворачивает базовую систему
  через **debootstrap** (Debian/Ubuntu, Astra Linux) или **dnf
  --installroot** (RedOS/RHEL-совместимые). BaseAlt/Alt Linux сознательно
  не поддерживается — см. `docs/ARCHITECTURE.md`.
- Позволяет подключиться к реальному репозиторию целевой ОС и выбрать
  пакеты для предустановки из фактического списка, а не набирать имена
  пакетов по памяти.
- Позволяет администратору просматривать журналы установленной ОС и
  обмениваться файлами с пользователем через отдельный раздел обмена.
- Выдаёт **код восстановления** по запросу от заблокированной переносной
  системы — без прямой передачи LUKS-пароля.

## Статус

Рабочий прототип с полным набором модулей и тестами (см. ниже). Все
деструктивные операции (разметка диска, `cryptsetup`, `mkfs`,
`debootstrap`/`dnf`) по умолчанию выполняются в режиме предпросмотра
(`dry_run=True`); экраны установки (и в GUI, и в TUI) умеют включать реальное
выполнение (отдельный переключатель + обязательное повторное подтверждение
пути устройства), но фактический успешный прогон на реальном внешнем
носителе ещё не подтверждён — см. `docs/ARCHITECTURE.md` "Известные
ограничения" для точного статуса по каждому бэкенду (Debian/RedOS/Astra) и
для того, что сознательно не реализовано (BaseAlt/Alt Linux).

Первая живая проверка на реальной RedOS-машине нашла и уже исправила два
реальных бага (носитель не находился автоматически из-за ненадёжного `RM`
у `lsblk`; просмотр пакетов из репозитория блокировал интерфейс и молча
обрезал список) и привела к добавлению второго интерфейса — см. следующий
раздел и `docs/ARCHITECTURE.md` "Обратная связь с первой реальной установки
на RedOS".

## Два интерфейса

- **GUI (Tkinter, по умолчанию)** — `portable-os-admin`. Пошаговые мастера:
  создание конфигурации и установка ОС разбиты на шаги, каждый со своей
  проверкой, а не одна большая форма с ошибками после заполнения всего.
- **TUI (Textual)** — `portable-os-admin-tui`. Прежний интерфейс, не удалён.

Оба работают поверх одной и той же бизнес-логики и одного формата
контейнера/конфигураций — можно свободно переключаться между ними на одной
машине.

## Требования

- Python 3.9+
- Для GUI — системный `tkinter` (пакет `python3-tk` на Debian/Ubuntu/Astra,
  `python3-tkinter` на RedOS/RHEL-семействе); при установке из `.deb`/`.rpm`
  подтягивается автоматически как системная зависимость.
- Для реальной (не dry-run) работы — Linux с `parted`, `cryptsetup`,
  `debootstrap` и/или `dnf`, правами root.
- Разработка и тесты возможны на любой Unix-системе (macOS/Linux) —
  деструктивные операции при этом просто не выполняются.

## Установка (разработка)

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## Запуск

```bash
python -m portable_os_admin.gui.app       # GUI (по умолчанию)
python -m portable_os_admin.tui.app       # TUI
# или, если пакет установлен:
portable-os-admin       # GUI
portable-os-admin-tui   # TUI
```

При первом запуске приложение предложит создать новый контейнер
администратора (путь + пароль) либо открыть существующий.

## Тесты

```bash
pytest
```

89 тестов покрывают криптографию, контейнер администратора, сеанс,
конфигурацию и её валидацию, планирование разметки диска и команд LUKS (без
реального выполнения), фильтрацию списка устройств (включая приёмку
USB-накопителей с ненадёжным `RM`-битом), бэкенды установки
(Debian/RedOS/Astra), оркестратор установки (dry-run), просмотр пакетов из
реального репозитория (с замоканной сетью), логику восстановления и
пользовательские сценарии в TUI (через headless `Pilot`) и в GUI (через
headless `tk.Tk()`), включая переключатель реального выполнения, экран
выбора пакетов и оба пошаговых мастера GUI.

## Структура проекта

```
src/portable_os_admin/
  crypto.py            # scrypt KDF, AES-GCM, генерация recovery-кода
  errors.py             # иерархия исключений
  session.py             # сеанс администратора
  container/            # контейнер администратора (шифрованное хранилище)
  config/               # файл конфигурации установки + валидация + repo_browser.py
  install/               # разметка диска, LUKS, бэкенды ОС, оркестратор установки
    backends/            # debian (debootstrap), redos (dnf --installroot), astra
  recovery/              # запрос/выдача кода восстановления + recovery_module.sh
  admin/                 # просмотр журналов, раздел обмена, сопоставление носителя
  gui/                   # Tkinter-приложение (по умолчанию), пошаговые мастера
  tui/                   # Textual-приложение (экраны = окна из спецификации)
tests/                    # pytest, 89 тестов
docs/ARCHITECTURE.md       # архитектура, трассировка требований, ограничения
packaging/                 # .deb (debian/) и .rpm (rpm/) для самого приложения
```
