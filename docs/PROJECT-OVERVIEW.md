## Что находится в коде

| Путь | Ответственность |
|---|---|
| `src/portable_os_admin/gui/` | Интерфейс приложения администратора на Tkinter, мастера и работа с правами администратора |
| `src/portable_os_admin/config/` | Структура конфигураций, проверки, обмен конфигурациями |
| `src/portable_os_admin/container/`, `crypto.py`, `session.py` | Зашифрованное хранилище администратора, ключи и сеанс |
| `src/portable_os_admin/admin/` | Обслуживание устройств, клиенты сервера, выпуски, журналы и восстановление |
| `src/portable_os_admin/install/` | Сборка ОС, разметка и запись устройств, загрузка, ограничения киоска, обновления |
| `src/portable_os_admin/install/backends/` | Различия Debian и РЕД ОС |
| `src/portable_os_admin/install/access/runtime/` | Программы переносного устройства: служба доступа, окно подключения, клиенты, сетевые правила |
| `packaging/revocation-server/` | Сервер доступа и управления: HTTP-сервер, API v2/v3, база, ключи, установка и кластер |
| `packaging/debian/`, `packaging/rpm/`, `packaging/polkit/` | Пакеты приложения и запуск с правами администратора |
| `tests/` | Автоматические проверки |
| `tools/stand/` | Скрипты и описание прежнего Linux-стенда |

Текущая реализация переносного устройства использует образы системы A/B, проверку dm-verity,
подписанные выпуски, зашифрованные служебные тома и временный слой изменений
в оперативной памяти. Код управления устройствами и сервером находится в
одном репозитории. Основной интерфейс этой ветки — Tkinter, не PySide6.

## Запуск и проверки

Для разработки на Linux с установленным Tkinter:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/portable-os-admin
```

Приложение запросит права через polkit. Проверки:

```sh
.venv/bin/python -m pytest -q --basetemp=/tmp/yakor-tests
.venv/bin/python -m pyflakes src packaging/revocation-server
.venv/bin/python packaging/revocation-server/poa-revocation-server.py --help
```

Для графических тестов нужен рабочий дисплей, для проверок сервера —
разрешение на локальные сетевые соединения и сокеты. Для полноценного
прогона нужны Linux, права администратора, установочные образы, тестовые
носители или образы дисков; для сценариев с токеном — соответствующий Рутокен
и библиотека производителя. Ранее использованный стенд описан в
[tools/stand/README.md](../tools/stand/README.md); его доступность здесь не проверялась.

### Результаты на Mac 05.11.2026

- Зависимости установлены в отдельное `.venv` (Python 3.9.6), импорт
  приложения и генератора загрузочного меню выполнен; проверены подпись
  загрузочного меню и вывод справки сервера.
- `pyflakes` для `src` и `packaging/revocation-server` прошёл без замечаний;
  `git diff --check` также прошёл.
- До изменений: **846 passed, 10 failed, 15 skipped** без графических тестов.
  После изменений, с коротким `--basetemp=/tmp/yakor-tests`:
  **851 passed, 5 failed, 15 skipped**, также без `tests/test_gui.py`.
  Для сетевых проверок запуск разрешён вне песочницы.
- Оставшиеся падения воспроизводились до изменений: одно — системная
  LibreSSL 2.8.3 не поддерживает проверяемый TLS 1.3; три — нет `/proc`,
  используемого для поиска процессов, удерживающих устройство; одно — нет
  Linux-механизма `binfmt_misc` для проверки сборки другой архитектуры.
  Пять ошибок длины UNIX-сокета исчезли после сокращения временного пути.
- **Интерфейс не проверен:** пробный запуск окна на системном Tk 8.5
  завис и был остановлен. Повторить на Linux с рабочим дисплеем:
  `.venv/bin/python -m pytest -q tests/test_gui.py`.
- **Сборка `.deb`/`.rpm`, установка на устройство и загрузка не проверены**
  в этой рабочей копии. Нужны Debian/РЕД ОС и стенд, описанный выше.
